About macOS

There is no Mac build at the moment.

Shelfcount used to ship Apple Silicon and Intel builds. It doesn't any more, and we aren't planning to bring them back until Shelfcount becomes a hosted app you open in a browser — at which point a Mac needs nothing but the browser it already has.

If you are already running Shelfcount on a Mac, it keeps working. Nothing has been taken away from a folder that is already on a laptop, and its data is yours in the same one file it always was. What stops is new versions: the app's update page says macOS is discontinued and offers no download, rather than pointing you at a file that isn't there.

Need a count done on a Mac in the meantime? The database file is identical across platforms, so a data/shelfcount.db copied to a Windows or Linux laptop opens there with every scan intact.

First launch

Unpack it with tar and skip the warning.

Shelfcount is deliberately not code-signed, so Windows will warn about it once — not because anything is wrong with the download, but because the operating system can't tell who built it. The warning comes from a flag your browser puts on the downloaded file, and tar doesn't copy that flag onto the files it extracts. So unpacking from a terminal avoids the warning entirely, and it's one line:

# Windows — PowerShell, in the folder you want Shelfcount to live in
tar -xf $HOME\Downloads\Shelfcount-win-x64.zip
# Linux — Terminal
cd ~/Downloads
tar -xzf Shelfcount-linux-x64.tar.gz

tar has shipped with Windows since Windows 10, so there is nothing to install for this.

If you unzipped it the usual way

It's a one-time click-through, per machine.

Windows: "Windows protected your PC" → More info → Run anyway.

Or clear the flag instead of clicking through it, once per folder:

# Windows — PowerShell, from inside the Shelfcount folder
Get-ChildItem -Recurse | Unblock-File

There is a third way that avoids all of this: if whoever manages your laptops can put the folder on the machine for you — management tools, a network share, a USB stick — nothing was downloaded by a browser, so nothing is flagged and nothing warns.

Then double-click the launcher — Shelfcount.bat on Windows, shelfcount.sh on Linux. A browser window opens at http://127.0.0.1:48620. That address is your own laptop: the app is running there, not on the internet.

Do not run it from inside the ZIP. Windows will happily show you the contents as though it were a folder, but launching from there gives you a read-only temporary copy and the inventory will be lost when it closes. Extract it first.

Checking what you downloaded

Every release publishes its checksums.

Each release carries a SHA256SUMS file covering both archives. Shelfcount's own updater verifies a download against it before unpacking anything, and you can check by hand:

PlatformCommand
Linuxsha256sum -c SHA256SUMS
WindowsGet-FileHash Shelfcount-win-x64.zip -Algorithm SHA256

Staying up to date

It notices new versions. It never restarts on you.

Notice
At most once a day, Shelfcount asks GitHub whether a newer release exists. A failed check is silent and never delays anything. You can turn the check off entirely.
Download
Only when you ask. The archive is verified against the release's published checksums before it is unpacked, and it lands in a staging folder that changes nothing.
Install
Only when you ask, and the swap happens at the next launch — never in the middle of a count. Your database is backed up first and the old version is kept, so a bad update can be undone.
Or don't
Swapping the folder by hand is still supported and always will be. Your data/ folder is never touched by an update.
